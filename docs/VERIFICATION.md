Дата: 2026-11-18 22:00 +04. Проверен реальный локальный Docker Compose на CachyOS Linux.

## Проверенные пользовательские операции

Регистрация, повторный логин, неверный пароль, вход, профиль, переименование,
загрузка с Unicode-именем, запрет анонимной загрузки, точный размер 1 МиБ и
отклонение превышения, совпадение скачанных байтов, метаданные без скачивания,
поиск/сортировка/пагинация, статистика владельца, уникальные скачавшие,
гостевые/повторные скачивания, запрет чужой статистики и удаления.
Проверены Web UI вход/выход, HttpOnly JWT-cookie, CSRF, multipart-форма,
HTML карточка, отчёт и удаление владельцем.

## Реальные отказы и восстановление

- S1, S2, S3, S4 останавливались целиком: API вместе с Worker.
  Независимые операции сохранялись; сообщения S3/S4 догоняли после старта.
- Отдельная остановка Reports Worker оставляла API на последней проекции.
- При отключении RabbitMQ upload коммитился в БД с Outbox; после старта
  событие автоматически доходило до каталога.
- При отключении RustFS upload/download возвращали 503, счётчик не рос;
  Auth и каталог оставались доступны.
- Повторное скачивание-событие не увеличивало счётчик повторно; скачивание
  до создания файла учитывалось после проекции; поздний create не отменял
  tombstone удаления. Несовместимая схема уходила в DLQ.
- Реальное пересоздание контейнера RabbitMQ сохраняло durable-очередь;
  пересоздание RustFS сохраняло байты и сервисные IAM credentials.
- Перезапуск Reports PostgreSQL восстанавливал доступ без перезапуска API.
- Сиротский объект с UploadIntent без живой блокировки удалялся Worker.
- В БД моделировалась зависшая ACTIVE-сессия: физический объект оставался
  до перезапуска S3; после получения process-lock новая API-инстанция
  закрывала сессию как FAILED и завершалось удаление.
- Проверены реальная kernel-блокировка живого API и гонка 12 параллельных
  скачиваний 1 МиБ с DELETE: успешные ответы содержали целые исходные байты,
  новые запрещённые сессии получали 409/410, объект удалялся после drain.

## Воспроизводимость и границы

Единый `python infrastructure/start.py` повторно выполнен успешно: сборка,
инициализация пользователей и очередей RabbitMQ, bucket/IAM RustFS,
миграции, запуск и ожидание готовности. Образы закреплены digest в
`infrastructure/images.json`, зависимости — в requirements.lock приложений.
Секреты не находятся в Git. Все проверки повторяемы скриптами в
`tests/integration/`.

Проверенная модель развёртывания — один Linux Docker-хост и один API-процесс
Download Service с общей локальной папкой блокировок. Это не проверка
многоузлового кластера. Граница успешного скачивания — серверная отдача;
сохранение на диск конечного клиента сервер доказать не может.
Разрыв ASGI-отдачи проверен отдельным юнит-тестом; аварийная сессия выше
моделировалась в PostgreSQL с реальным перезапуском API.
Тестовые пользователи остаются, тестовые бинарные файлы удалены.
В DLQ сохранены намеренно отправленные события с event_version=999.
