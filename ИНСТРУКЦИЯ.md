# AMPIS: запуск и отключение модулей

Все команды выполняй из папки проекта:

```bash
cd /home/srx/Proga/AMPIS
```

## 1. Запустить и остановить систему

Запустить:

```bash
docker compose up -d --wait
```

Открыть сайт: **[http://localhost:8080/app/](http://localhost:8080/app/)**.

Посмотреть состояние:

```bash
docker compose ps -a
```

В обычном режиме работают **15 контейнеров**. После отключения модуля его
контейнеры показываются как `Exited`; после включения дождись готовности.

Остановить всё, сохранив данные:

```bash
docker compose stop
```

Включить всё обратно, в том числе после экспериментов с отключениями:

```bash
docker compose up -d --wait
```

Если Docker не запущен: `sudo systemctl start docker`.

## 2. Что есть что

| Модуль | Назначение | Контейнеры приложения |
|---|---|---|
| G1 — Gateway | Сайт и единая точка входа | `gateway` |
| S1 — Auth | Регистрация, вход, изменение имени | `auth-api`, `auth-worker` |
| S2 — Upload | Загрузка и удаление файлов | `upload-api`, `upload-worker` |
| S3 — Download | Скачивание, история и активные передачи | `download-api`, `download-worker` |
| S4 — Reports | Каталог, поиск, сортировка, страницы и статистика | `reports-api`, `reports-worker` |
| D1 — RabbitMQ | Обмен событиями между сервисами | `rabbitmq` |
| RustFS | Хранение байтов файлов | `rustfs` |

`api` принимает запросы, `worker` обрабатывает фоновые события.
У S1–S4 отдельные БД: `auth-db`, `upload-db`, `download-db`, `reports-db`.
**Чтобы отключить сервис для проверки задания, останавливай его API и Worker
вместе. Базы данных для этих сценариев оставляй включёнными.**

В папке проекта: `gateway/` — сайт, `services/` — сервисы,
`docker-compose.yml` — состав системы, `infrastructure/` — подготовка,
`tests/` — проверки, `docs/` — требования и результаты.
`.env` и `secrets/` содержат локальные пароли и ключи.

## 3. Как пользоваться

Зарегистрируйся, затем войди. Логин: 3–64 символа из латиницы, цифр, `_`, `.`,
`-`; пароль — от 10 символов. Через **Загрузить** отправь файл до 1 МиБ.
Каталог и скачивание доступны без входа. Статистика и удаление — владельцу.
Через **Профиль** можно изменить имя.

Новый файл, имя и счётчик могут появляться с небольшой задержкой: подожди
и обнови страницу. Удаление сначала планируется, затем завершается после
активных скачиваний. Вход действует один час.

## 4. Задание: отключить S2, S3 или S4

**Проверяй по одному сервису. После каждого опыта включай его обратно.**
Перед началом загрузи небольшой файл и дождись его появления в каталоге.

### S2 — загрузка и удаление

Отключить:

```bash
docker compose stop upload-api upload-worker
```

Проверь: вход, каталог, поиск и скачивание старого файла работают.
Загрузка и запрос удаления недоступны.

Включить:

```bash
docker compose start upload-api upload-worker
```

### S3 — скачивание

Отключить:

```bash
docker compose stop download-api download-worker
```

Проверь: вход, загрузка, каталог и поиск работают. Скачивание недоступно.
Запрос удаления принимается, но физическое удаление ждёт восстановления S3.

Включить:

```bash
docker compose start download-api download-worker
```

После восстановления новые файлы становятся доступны для скачивания,
а ожидающие удаления операции завершаются.

### S4 — каталог и статистика

Перед отключением сохрани ссылку **Скачать** на уже загруженный файл.

Отключить:

```bash
docker compose stop reports-api reports-worker
```

Проверь: вход и загрузка работают. Скачивание по сохранённой ссылке работает.
Каталог, карточки и статистика недоступны, поэтому главная страница может
показать ошибку каталога. Для проверки входа открой
[страницу входа](http://localhost:8080/app/login), загрузки —
[форму загрузки](http://localhost:8080/app/upload).

Вход и загрузка перенаправляют в каталог, поэтому итоговая страница может
показывать ошибку S4 даже при успешной операции. Загруженный файл станет
виден после восстановления S4.

Включить:

```bash
docker compose start reports-api reports-worker
```

Каталог автоматически догонит накопившиеся изменения.

## 5. Задание: отключить S1 и проверить работу без регистрации

Отключить:

```bash
docker compose stop auth-api auth-worker
```

Открой сайт в приватном окне браузера, чтобы проверять **без входа**.
Каталог, поиск и скачивание старых файлов должны работать.
Регистрация, новый вход и изменение профиля недоступны.

Включить:

```bash
docker compose start auth-api auth-worker
```

## 6. Задание: отключить D1S4, затем восстановить

D1S4 — доставка событий от шины к Reports. Для демонстрации останови
**только `reports-worker`**. `reports-api` и `rabbitmq` оставь работать.

1. Загрузи файл и дождись его появления в каталоге.
2. Отключи получение событий:

   ```bash
   docker compose stop reports-worker
   ```

3. Загрузи второй файл, измени своё имя или скачай первый файл.
4. Обнови каталог. Он доступен, но показывает данные на момент отключения:
   нового файла ещё нет, имя и счётчик могут оставаться старыми.
5. Включи получение событий:

   ```bash
   docker compose start reports-worker
   ```

6. Подожди немного и обнови страницу. Файл, имя и счётчик обновятся
   автоматически после обработки очереди.

## 7. Другие отключения и полезные команды

Эти отключения — дополнительные опыты, отдельно от трёх сценариев задания.

| Что отключить | Отключение | Включение | Что произойдёт |
|---|---|---|---|
| Весь сайт G1 | `docker compose stop gateway` | `docker compose start gateway` | Пользовательские страницы и API недоступны. |
| Шину D1 целиком | `docker compose stop rabbitmq` | `docker compose start rabbitmq` | Существующий каталог и известные Download файлы доступны. Обновления через события догонят после восстановления. |
| Хранилище байтов | `docker compose stop rustfs` | `docker compose start rustfs` | Загрузка и скачивание недоступны; вход и каталог продолжают работать. |
| БД авторизации | `docker compose stop auth-db` | `docker compose start auth-db` | Регистрация, вход и профиль недоступны; публичные каталог и скачивание работают. |

Для остальных БД используются имена `upload-db`, `download-db`, `reports-db`.
Остановка БД делает недоступными зависимые операции соответствующего сервиса.

Логи нужного модуля:

```bash
docker compose logs --tail=50 upload-api upload-worker
docker compose logs --tail=50 reports-worker
```

Перезапуск модуля:

```bash
docker compose restart upload-api upload-worker
```

`stop` сохраняет контейнеры и данные. `down` удаляет контейнеры и сети,
но сохраняет тома. Флаг `-v` удаляет тома — для обычных проверок он не нужен.
Не удаляй `.env`, `secrets/` и `.runtime/` во время работы системы.

## 8. Первый запуск, обновление и автоматическая проверка

Для первого запуска нужны Docker Compose, Python 3.14 и интернет.
Команды ниже для Bash; если терминал использует Fish, сначала введи `bash`.

```bash
bash
cd /home/srx/Proga/AMPIS
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python infrastructure/start.py
```

Скрипт подготовит конфигурацию, соберёт образы, настроит хранилища и очереди,
запустит систему. На уже настроенном проекте после изменения кода достаточно:

```bash
source .venv/bin/activate
python infrastructure/start.py
```

Обычный `restart` изменённый код в образ не добавляет.

Автоматически проверить пункты задания при работающей системе:

```bash
source .venv/bin/activate
python tests/integration/assignment_check.py
```

Проверка временно отключает модули и создаёт тестовые записи.
Полный разбор соответствия: [docs/ASSIGNMENT_REVIEW.md](docs/ASSIGNMENT_REVIEW.md).
